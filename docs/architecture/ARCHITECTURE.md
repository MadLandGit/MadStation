# Mad Station architecture (migration snapshot)

This is an in-place migration of the Mad Station 1.5.4 source baseline, now prepared as application version 1.6.3. The live product architecture and established UI are preserved while TypeScript/React replaces bounded, testable subsystems. It is **not yet a fully TypeScript main process or fully React workspace**: the remaining legacy boundary is explicit below.

## Process and trust boundaries

The main-process migration includes **source-level security remediation** (v38). `src/main.js` remains the composition root, while typed modules own domain and network-policy helpers including `network-security.ts`, `public-suffix-list.ts`, `account-session-security.ts`, and the lifecycle/orchestration domains listed below. The bundled Public Suffix List source identifies upstream version `2026-10-16_09-29-46_UTC` (commit `91b4bd846240a84afb33695d5a51adcbc4cfd9ca`, 10,399 rules); see `src/main/public-suffix-list.ts` for provenance and `AGENTS.md` for the refresh workflow. The latest owner-provided Windows diagnostic reports the configured release checks passed for the diagnosed working copy; that point-in-time evidence does not replace targeted security tests or future revalidation after source changes.

Domain modules include `ai-lab-runtime.ts`; `arena-store-runtime.ts`, `arena-account-data-runtime.ts`, `arena-browser-runtime.ts`, and `arena-prompt-runtime.ts`; `forge-browser-runtime.ts`; `video-hub-browser-runtime.ts` and `video-hub-network-runtime.ts`; `account-browser-runtime.ts`; and `native-operations-runtime.ts`. Shared lifecycle/attachment/layout/security adapters include `session-lifecycle-runtime.ts`, `web-contents-view-attachment-runtime.ts`, `browser-view-layout-runtime.ts`, `workspace-browser-events.ts`, and `account-session-security.ts`.

Keep the distinction clear: these modules own domain orchestration, while the main process still injects Electron primitives, trusted sender/lock enforcement, `hardenAccountContents`, mutable application/workspace state, IPC registration and native effects. Do not treat source regression tests, standalone typechecks, or a startup smoke check as proof that every live security scenario is safe; see the current checkpoint for the exact automated and owner-confirmed evidence boundaries.

## Responsibilities

- **`src/main.js`** still owns application lifecycle, native windows and views, account/browser/session lifetimes, IPC handler authorization, persistence orchestration, OS/file integration, and shutdown. Keep it as the trusted host while moving cohesive handler families into typed modules; do not port the file by renaming it or hiding type errors.
- **`src/main/settings.ts`** contains pure settings/security DTOs, safe normalization and defaults. It does not import Electron or access the filesystem.
- **`src/main/settings-controller.ts`** owns typed transitions for general settings, security settings, download preferences and reset-to-defaults. `src/main.js` retains the trusted `handle()` wrapper, Electron side effects, and config broadcast/persistence callbacks injected into the controller. Keep channel authorization and lock checks in `handle()`; add business behavior and tests in the controller.
- **`src/main/config-schema.ts`** owns persisted provider/account normalization and backward-compatible config migration. It accepts injected ID, shortcut, lock, provider-default and settings-normalizer dependencies rather than importing Electron.
- **`src/main/downloads.ts`** owns download-specific types, filename sanitization, unique path selection, managed download source failover, download lifecycle state and renderer-facing download DTOs. Electron's shell is injected, allowing the manager to be tested independently.
- **`src/main/icon-cache.ts`** owns remote icon URL validation, bounded HTTPS retrieval, MIME checking, persisted cache metadata, disk/memory bounds and release behavior.
- **`src/main/input-validation.ts`** owns typed text/ID/HTTPS/icon/host helpers reused by trusted main-process workflows. These helpers do not replace channel-specific IPC authorization or business validation.
- **`src/main/video-hub-ipc.ts`** defines the typed Video Hub IPC command contract and maps the existing channel names to injected host commands. It deliberately does not own persistence or browser/session lifecycle; registrations still receive the existing secure `handle()` wrapper.
- **`src/main/video-hub-controller.ts`** owns typed Video Hub provider/account DTOs, default/legacy-store normalization, renderer state mapping, unique names, and low-coupling add/rename transitions. It receives store and validation dependencies; `src/main.js` retains file recovery/atomic writes and every session/view/proxy operation.
- **`src/main/ai-hub-controller.ts`** owns typed AI Hub provider/account create/update/rename/shortcut transitions and validation. Account updates are prepared before mutation so `src/main.js` can dispose the live browser view first, then apply the patch and clear session state in the established order. IPC sender/lock/payload checks, config save/broadcast, remote icon warming, account activation, and browser/session cleanup remain in main.
- **`src/main/ai-hub-ipc.ts`** registers the AI Hub provider/account CRUD, ordering, and account-maintenance channel family. It receives the existing secure `handle()` registrar and forwards arguments to injected commands; config/session side effects remain in the main-process composition root.
- **`src/main/ai-hub-read-model.ts`** owns provider/account ordering helpers and the typed AI Hub renderer read-model projection. Icon resolution, account runtime status, base settings metadata, and access to persisted config are injected by `src/main.js`; locked-state projection remains deliberately empty.
- **`src/shared/ipc-validation.ts`** is the shared generic data-structure validator. It prevents cycles, non-plain objects, forbidden prototype keys, unsupported primitive values and oversized/deep payloads. It is not a substitute for business validation and per-channel authorization in `src/main.js`.
- **`src/preload.ts`** exposes the existing `window.aiHub` compatibility API. **`src/toolbar-preload.ts`** exposes only `window.aiHubToolbar`. Neither exposes arbitrary IPC channels, Node `fs`, `shell`, or raw Electron objects. Event subscriptions return cleanup callbacks.
- **`src/renderer-react/home-mini-apps.tsx`** owns the icon-only shortcut tile subtree in `#homeMiniApps`; `src/home-mini-apps.js` retains the registry, preferences, routing handoff, positional offsets, and Home Core integration, but no longer creates tile DOM. The React view preserves `.home-mini-app-tile`, `data-app-id`, `--mini-offset`, and dispatches `mad:home-mini-apps-built` after commit so signal-line discovery sees the rendered tiles.

Once the React bundle signals readiness, it returns before the legacy branch can write the same subtree, including empty states.

## IPC invariants

1. Keep `contextIsolation: true`, `nodeIntegration: false`, and `sandbox: true` where currently configured.
2. Expose only named, narrow operations through preload. Never expose raw IPC, filesystem or Electron objects.
3. Main handlers check trusted sender/main frame and locked-state policy before accepting payloads. Keep additional toolbar-specific authorization.
4. All renderer payloads are untrusted. `isSafeIpcPayload` validates bounded plain-data shape only; every channel still validates IDs, HTTPS URLs, enum values, resource ownership and operation-specific invariants.
5. Preserve local-file loading/navigation/popup restrictions and exact toolbar-development URL authorization.
6. Do not log credentials, API keys, cookies, session tokens, full URLs containing tokens or clipboard contents.
7. Every event subscription must return and use a cleanup callback.

- **Change Home mini-app tile UI:** edit `src/renderer-react/home-mini-apps.tsx`; preserve `.home-mini-app-tile`, `data-app-id`, `--mini-offset`, title/accessibility labels, and the post-commit `mad:home-mini-apps-built` notification so Core can discover signal-line endpoints. Keep registry and launch routing in `src/home-mini-apps.js`.
- **Change the Home companion card UI:** edit `src/renderer-react/home-companions.tsx`; preserve `.home-module` hooks, More-apps focus/outside-click behavior, registry callbacks, and Home Core links. Keep custom chip content as text.
- **Change account card UI:** edit `src/renderer-react/account-list.tsx`; reuse current class names and test active, empty, filtered, drag/reorder and icon-fallback states. Account persistence and actions remain supplied by `src/renderer.js` until those domains migrate.
- **Change Clipboard, Notes or To-do list UI:** edit `src/renderer-react/utility-lists.tsx`; keep persistence, sorting/filter state and mutations in the existing controller until their business logic is deliberately extracted. Do not mutate any React-owned utility-list root with `innerHTML` after the handoff.
- **Change global settings normalization:** edit `src/main/settings.ts`; avoid Electron imports, validate persisted unknown input, add regression tests and preserve backwards-compatible defaults.
- **Change persisted account/provider schema:** edit `src/main/config-schema.ts`; retain account IDs, existing provider matching, shortcuts, ordering, config version and legacy starter migration. Add migration fixtures in `tests/main-config-schema.test.js`.
- **Change config persistence/recovery:** edit `src/main/config-store.ts`; preserve atomic rename, best-effort backup, primary quarantine and backup fallback. Add filesystem-backed tests in `tests/main-config-store.test.js`.
- **Change app-lock security:** edit `src/main/lock-security.ts`; never accept persisted scrypt parameters as trusted work factors; keep constant-time hash comparison and escalating attempt delays. Test using `tests/main-lock-security.test.js`.
- **Change downloads:** edit `src/main/downloads.ts`; renderer must supply download IDs, not filesystem paths. Add tests for Windows filename rules, source selection, progress/finalization and program-file restrictions.
- **Change icon caching:** edit `src/main/icon-cache.ts`; preserve HTTPS-only validation, MIME allowlist, cache bounds, atomic index writes and RAM release.
- **Expose a native action:** define DTO/API in `src/shared/api-contract.ts`, implement a named method in the appropriate preload, add sender/lock/payload/business validation in the main handler, and test the main boundary. Do not put privileged APIs in React.
- **Change other workspace DOM:** follow `docs/architecture/CORE_SYSTEM.md` and the screen-specific modules. Keep DOM IDs and `data-*` hooks; no second renderer should mutate a React-owned region.
