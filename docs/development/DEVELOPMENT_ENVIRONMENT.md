## First lockfile creation (only when no lockfile exists)

A lockfile must be generated by npm against the actual registry metadata; do not hand-author it. On a network-enabled, trusted machine using the pinned Node/npm versions:

```bash
node --version       # must be v22.16.0
npm --version        # must be 10.9.2
npm install --package-lock-only --ignore-scripts --no-audit
```

Review `package-lock.json` before committing it. Confirm it is lockfile version 3, contains exact versions plus `resolved`/`integrity` metadata for registry packages, and its root metadata matches `package.json`. Do not accept unexpected registry hosts, git/file dependencies, manifest drift, or unresolved lifecycle-script warnings. Do not use a generated lockfile from a different branch/revision.

## Reproduce from a clean checkout

Once a reviewed lockfile is committed:

```bash
npm ci
npm run env:check
npm ls --depth=0
npm run typecheck
npm test
npm run build
npm run audit
```

`npm test` invokes its `pretest` build, so `esbuild` must be installed. `npm run build` checks types, builds the Vite renderer, bundles preloads and bundles the typed main modules. Run the Windows packaging command only after these checks pass; installer/runtime tests are a separate gate.

`npm run env:check` verifies the pinned Node/npm versions, lockfile version and manifest consistency, installed direct dependency versions, and the local TypeScript/Vite/esbuild/Electron/Electron Builder executables. `prebuild`, `pretypecheck`, `pretest` and `predev` run this guard so an incomplete or drifting setup fails early with a concrete reason.
