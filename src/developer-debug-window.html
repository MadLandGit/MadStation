    09

    Element Explorer

    Search every DOM element in the currently visible app page or built-in homepage theme, including hidden nodes, non-rendering tags, and descendants of open shadow roots. Highlighting a hidden result temporarily reveals it for inspection.

    Search the current page to list matching elements.Page —
    Enter a search term or choose Refresh all to enumerate page elements.
    For performance, each page displays up to 50 results. Searching scans the complete active document, not just the visible viewport. Closed shadow roots and isolated third-party pages are not inspectable by design.

    10

    Visual Debug Legend

    What the colored lines, boxes, labels, and overlays mean. Multiple diagnostics can target the same element; the most specific highlight may cover the basic outline.

    Thin red / pink outline — every element

    The baseline outline is applied to DOM elements so you can see their boundaries, including elements with no visible background.

    Outline Elements
    Blue / cyan outline — layout containers

    Marks likely structural elements such as sections, headers, navigation, cards, panels, grids, forms, and layout wrappers.

    Outline Elements
    Bright green outline — interactive controls

    Marks buttons, links, inputs, select boxes, text areas, ARIA buttons, and elements with a tabindex. This rule is drawn over the basic container outline.

    Outline Elements
    Lime dashed outline — keyboard-focusable

    Shows controls and elements reachable by keyboard navigation. It can overlap or replace the normal outline.

    Highlight keyboard-focusable controls
    Thick red outline / red inset — overflow

    Marks elements the overflow audit identified as extending beyond their bounds or the available viewport. Check width, height, overflow, and child positioning.

    Highlight overflow
    Magenta outline — element under pointer

    Highlights the exact element currently hovered when hover inspection is enabled.

    Highlight element under pointer
    Amber / yellow outline and glow — selected element

    Appears briefly after you choose Highlight in Element Explorer. It identifies the specific search result selected for inspection.

    Element Explorer → Highlight
    Amber floating card — hidden element revealed

    When you highlight a hidden search result, the Inspector temporarily reveals the selected node at the top-left of the page and opens hidden ancestors. The original styles are restored after about four seconds.

    Element Explorer → Reveal & highlight
    Translucent blue fill / inset edge — container tint

    Adds a subtle tint to probable layout containers to make wrapper regions, nested panels, and structural blocks easier to distinguish.

    Tint layout containers
    Blue grid lines — spacing grid

    The brighter major lines repeat every 16 pixels; finer, fainter lines repeat every 4 pixels. Use them to compare padding, gaps, and alignment.

    Show 16 px layout grid
    tag#id
    Gold labels — element identity

    Small badges identify an element by tag, ID, and classes. They are annotations, not part of the actual page layout.

    Label elements and IDs
    Dark panel with cyan edge — inspector window

    This is the separate Developer Inspector itself, not a page element. Its outline helps distinguish the diagnostics window from overlays drawn over the app.

    Separate desktop window

    Box model — numbers in the Inspector, not a page overlay

    Padding, border, and margin measurements are shown in the Layout & box model section. This option adds measurement data; it does not paint another colored box over the app.

    Show box model details
    i
    Inspector-only diagnostics — no colored line

    Hit-test stack, last-click trace, hidden-node audit, duplicate IDs, fixed/sticky counts, accessibility fields, and computed CSS appear in the separate Inspector window rather than being drawn onto the page.

    Interaction diagnostics / Page overview
    Why colors can look mixed: one element may be both a container and a button, or both overflowing and hovered. CSS rules overlap by design. Hover magenta and selected amber highlights are especially specific; toggle options one at a time to isolate a boundary.
